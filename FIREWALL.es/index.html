Funciones de seguridad¶

English | Français | Español | Deutsch | Русский | 日本語 | Português | 中文

Wiretap añade una capa de caza de amenazas sobre la observación pasiva. Qué hace — e igual de importante, qué no hace:

Orquestación del firewall de salida¶

Wiretap no filtra paquetes en user-space. Las reglas se aplican al firewall nativo del SO, best-effort:

SO Mecanismo
Windows reglas de bloqueo de salida netsh advfirewall
Linux iptables -A OUTPUT -j DROP (cadena WIRETAP_LOCK para el lockdown)
macOS anchor pf generada cargada con pfctl

Tipos de regla: ip, cidr, domain (resuelto una vez al aplicar), process, port. Las reglas persisten en wiretap.db y se reaplican al arrancar.

Límites honestos:

  • Aplicar reglas exige los mismos privilegios que la captura. Sin elevación, applied=False queda en la regla — la UI muestra «solo visibilidad». El matching sigue activo: los paquetes que violan una regla levantan alertas BLOCKED_ATTEMPT con contadores por regla.
  • pf en macOS no puede casar un proceso — las reglas de proceso ahí son solo visibilidad, por diseño.
  • Las reglas domain resuelven el nombre una vez; una CDN que cambia de IP se salta la regla hasta recrearla.
  • Lockdown solo corta el tráfico de salida hacia IP públicas — loopback y LAN quedan vivos para que la UI siga accesible.

Respuesta a incidentes¶

  • POST /processes/kill / POST /processes/suspend — por PID, rechaza PID ≤ 3 y al propio Wiretap. Privilegios normales del SO.
  • POST /firewall/rules, DELETE /firewall/rules/{id}, POST /firewall/rules/{id}/toggle, POST /firewall/lockdown — autenticados como todo endpoint.
  • GET /forensics/export?process=<nombre>&ip=<ip> — paquete de investigación: árbol de procesos (hasta 8 ancestros), SHA-256 del ejecutable, cmdline, alertas asociadas, historial por minuto. format=json|csv|stix elige la salida (STIX = bundle 2.1 minimal para SIEM). Datos locales solo; la exportación es una descarga, nunca una subida.

Threat intelligence — opt-in, desactivado por defecto¶

Ajustes → Threat intelligence acepta un proveedor (abuseipdb, otx, virustotal) más tu propia clave API. Activado, cada nueva IP pública se verifica una vez por TTL de 24 h; los veredictos se cachean y un veredicto suspicious/malicious emite una alerta THREAT_HIT. Sin proveedor ni clave, cero llamadas salientes. GET /security/ti muestra la config enmascarada; POST /security/threat_check lanza una verificación manual (también consciente del caché).

Webhooks — opt-in, desactivados por defecto¶

Ajustes → Webhook externo acepta una URL y un interruptor. Las alertas warning y críticas se POSTean en vivo: Discord/Slack {content}, Telegram {chat_id, text} (campo chat ID si es URL de telegram), cualquier otro endpoint recibe {alert, source, text}. Los fallos se loguean, nunca son fatales.

Nuevas detecciones¶

  • DNS_TUNNEL — nombres/labels DNS sobredimensionados (>60 car. / label

    40), patrón clásico de exfiltración; una vez por host por 10 min.

  • CLEARTEXT — TCP saliente a puertos no cifrados por naturaleza (80, 21, 23, 25, 110, 143…), nivel INFO, alimenta la auditoría.
  • BASELINE_DEVIATION — cada proceso aprende sus países de destino habituales en sus primeros paquetes y luego avisa una vez al alcanzar uno nuevo. Los baselines persisten (app_baselines).
  • BEACON — ya existente: intervalos regulares (CV de tiempos de inter-llegada) incluso con tráfico mínimo.
  • BLOCKED_ATTEMPT, LOCKDOWN, THREAT_HIT — tipos añadidos por los módulos anteriores.

Auditoría de seguridad¶

GET /security/audit calcula un score 0–100 desde las últimas 500 alertas y el grafo: conteos por tipo, contactos con países de riesgo, hosts sin resolver, postura del firewall — y devuelve recomendaciones en lenguaje claro. Es un informe de hallazgos, no una certificación.

Novedades v1.2 / Nouveautés v1.2¶

  • Acción sinkhole — las reglas domain/ip pueden redirigir a loopback en lugar de bloquear: dominios vía un bloque marcado # wiretap-sinkhole en el archivo hosts (todos los SO), IP/CIDR vía DNAT iptables (solo Linux). sinkhole en process/port se rechaza; plataformas no soportadas → applied=False honesto.
  • Re-resolución de dominios — las reglas domain se re-resuelven cada ~10 min y el delta de IP se aplica por SO, para que la rotación CDN no desbloquee un nombre en silencio.
  • Vigilancia de integridad (activada por defecto, solo lectura, local) — baselines SHA-256 de ejecutables en red (BINARY_CHANGED), nombres/exe divergentes (NAME_MISMATCH), scan rwxp solo Linux (MEM_RWX, nivel info para apps JIT conocidas). GET /security/integrity, POST /security/integrity/check.
  • Explicaciones de alertas — GET /security/explain?type=X devuelve explicaciones bilingües (EN/FR) escritas a mano; deterministas y offline — no es un modelo. La UI las muestra tras el botón "¿Por qué?".

Sondas opcionales (v1.3)¶

Todas están desactivadas por defecto o se autolimitan, degradan honestamente y nunca envían datos fuera de la máquina:

  • Sonda eBPF connect (Linux, ajuste ebpf_probe) — kprobe BCC tipo tcpconnect que atribuye connect() de procesos demasiado efímeros para la tabla de sockets. Requiere python3-bcc + root; destinos ambiguos nunca se adivinan. GET /security/ebpf.
  • Inspección Frida — POST /security/deep_inspect {pid,seconds} adjunta a UN pid ≤60 s y reporta qué módulo cargado emitió cada connect(). Rutas de módulos en temp/staging → INJECT_SUSPECT.
  • Respondedor sinkhole — con una regla sinkhole activa, listeners loopback en :80/:443 convierten cada intento en alerta SINKHOLE_HIT con Host/URI o SNI + proceso.
  • Integridad de módulos — raíz Merkle sobre los mapeos ejecutables → MODULE_CHANGED; rutas en /tmp/memfd → MODULE_SUSPECT.
  • Detección de minería — JSON stratum en cabecera de payload → MINING_STRATUM; puertos de pool + CPU sostenida → MINING_SUSPECT.
  • Contadores hardware — POST /security/perf muestrea ciclos/instrucciones vía perf_event_open (Linux).
  • LLM local — opt-in (slm_enabled): /security/explain llama a un endpoint Ollama solo loopback — endpoints remotos rechazados.
  • Paquetes IOC — GET /security/iocpack exporta un Bloom + randomized response (nunca en claro); POST /security/iocpack/import comprueba destinos de forma probabilística.

Novedades de política y respuesta (v1.4)¶

  • Perfiles nombrados — POST /firewall/profile: permissive (tabla rasa), balanced (base de salida prudente) o strict (base + lockdown); se expanden en reglas ordinarias con deduplicación.
  • Reglas de alerta personalizadas — GET/POST/DELETE /alerts/rules: campo + operador + valor → alertas CUSTOM_RULE (solo alerta, nunca bloquea).
  • Importar blocklist — POST /firewall/blocklist: archivo local (local puro) o URL opt-in (fetch HTTPS ≤4 MiB, señalado remote_fetch) → reglas domain, deduplicadas, tope 500–5000.
  • Export PCAP — GET /forensics/pcap (filtros ip/process): anillo de tramas ~4 MiB como .pcap para Wireshark.
  • Emparejamiento remoto — POST /remote/pairing persiste lan_bind para el próximo inicio; el token sigue obligatorio. GET /remote/pairing reporta bind + IPs LAN.
  • Sandbox sin red — POST /security/sandbox ejecuta un binario con cero egress (unshare -n Linux, sandbox-exec macOS; contrib/wiretap-contain manual).
  • Modelo embebido — slm_mode=embedded carga un .gguf del usuario vía llama-cpp-python — cero red.
  • Esqueletos nativos — contrib/wfp-callout/ (callout WFP en C + firma) y contrib/macos-filter/ (NEFilterDataProvider Swift + entitlements): scaffolding de investigación, no se distribuyen.
  • ASN — con GeoLite2-ASN.mmdb/dbip-asn-lite.mmdb, los nodos llevan asn además de org.

v1.5 — Inspección pasiva, veredictos en kernel y sincronización de flota¶

  • Inspección pasiva del certificado TLS — reensamblado TCP limitado (≤16 KiB/flujo, TTL 30 s) lee el mensaje Certificate: CN+O emisor/sujeto, autofirmado, SANs, validez, san_mismatch → TLS_CERT. TLS 1.3 queda opaco — honestamente inobservable en vez de adivinar.
  • Guardia de alta entropía — payloads ≥48 B en canales no TLS con ≥4,7 bits/byte → HIGH_ENTROPY; cooldown 10 min por host.
  • Heurística de túnel ICMP — tipos echo con ≥24 B de payload, ≥3× en 5 min → ICMP_TUNNEL.
  • Anomalía ML de flujo — isolation forest en Python puro (64 árboles, cero deps) sobre tus propios resúmenes; inerte <384 flujos, ML_ANOMALY a 0,62. Desviación de baseline, no un clasificador.
  • Ask-on-connect (Linux, opt-in) — ask_enabled + root + iptables: nuevos flujos salientes retenidos en NFQUEUE 7 hasta POST /security/ask/verdict — el cliente NFQUEUE es Python puro (detection/nfqueue.py, AF_NETLINK), sin python-netfilterqueue; timeout 15 s, fail-closed (ask_failopen=1 invierte). Windows/macOS necesitan los esqueletos firmados de contrib/.
  • Enforcement eBPF cgroup (Linux, opt-in) — POST /security/ebpf/isolate {pid} + /security/ebpf/block {ip}: programa attach al cgroup wiretap — drops en kernel SOLO para procesos aislados.
  • Check de hollowing (Linux) — POST /security/hollow {pid} compara páginas ejecutables file-backed de /proc/<pid>/mem con el disco.
  • Sincronización IOC entre pares (opt-in) — gossip_peers ≤32 + gossip_enabled: paquetes Merkle cada 5 min por HTTP(S) autenticado — sin discovery, no es ZK.
  • Syslog (opt-in) — syslog_addr (host:puerto UDP o tcp://) → RFC 3164 local4.
  • Contención Firejail — firejail --net=none preferido, unshare como fallback.
  • Backend nftables — tabla inet wiretap dedicada en lugar de iptables donde existe nft.
  • Alertas accionables — actions estructuradas (bloquear IP, matar/suspender, veredicto ask) como botones de un clic.
  • asn/country en reglas custom — base geo local, combinable con action=block como geo-fence.
  • Heurística DGA — los nombres DNS resueltos y SNIs TLS se puntúan por rasgos léxicos (entropía, vocales, consonantes apiladas, dígitos) → DGA_SUSPECT. Heurística local pura; sin WHOIS ni edad de dominio.
  • Protocolo disfrazado — la cabecera ≤64 B del payload debe coincidir con el protocolo del puerto (HTTP/80, DNS/53, SSH/22, TLS/443+853, comandos ASCII de correo) → PROTO_MISMATCH, con cooldown por flujo.
  • Kill-switch de volumen (opt-in) — kill_switch_enabled convierte un UPLOAD_SPIKE en un bloqueo de firewall real sobre la IP remota (deduplicado, best-effort). Desactivado por defecto.
