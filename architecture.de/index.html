Zentrale Invarianten

  • Keine per-Paket-Coroutines oder -Broadcasts — eine Queue, ein Drain-Task, eine batch-WS-Nachricht pro ~250 ms.
  • remote_port ist überall richtungsbewusst; dst_port wird nie zur Klassifikation genutzt (eingehend ist es ein lokaler Port).
  • Kein Drittanbieter-Aufruf existiert im Code ohne explizites Opt-in.
  • Der Detector hält einen Lock um allen veränderlichen Zustand; jeder Container ist größenbeschränkt.
  • macOS: Media-Monitoring meldet supported: false; die UI blendet das Badge aus.

Schichten im Überblick

  • Capture: pcap.py (ctypes → libpcap/Npcap) + eigener parser.py (Ethernet, IPv4/IPv6 mit Extensionen, TCP/UDP, DNS-Antworten, TLS-SNI).
  • Pipeline: begrenzte Queue → ein Drain-Task (~4 Hz) → eine batch-WS-Nachricht pro Tick.
  • Klassifikation: immer über remote_port (richtungsbewusst).
  • Anreicherung: beobachtetes DNS/SNI > Reverse-DNS > lokale .mmdb; deduplizierte Tasks, Fehler nie dauerhaft gecacht.
  • Sicherheit: firewall.py orchestriert die OS-Firewall (netsh/iptables/pf) mit persistierten Regeln, Lockdown und Blockzählern; threatintel.py macht Opt-in-Reputationsabfragen mit LRU-Cache.
  • Persistenz: Traffic-Aggregate, Alarme und Einstellungen in SQLite; Flush beim Stoppen; konfigurierbare Aufbewahrung.
